People searching "Fortify email verification Vue" build a second verification controller. The Vue starter kit already has the pages. The [Fortify guide](/laravel-fortify-vue) is the login post. This page is the switch that actually sends the mail.

<TLDR audience="Laravel + Vue developers" applies="Laravel 13 · Vue 3">

- The Vue starter kit already verifies email.
- The user model must implement MustVerifyEmail, and the resend form posts to Fortify.
- Do not replace it with a Vue route that reads `?id=` and marks the user verified.
- Do not log the verification URL.

</TLDR>

## The fix

In `config/fortify.php`, the feature list includes email verification. The user model has to implement the contract or Fortify will not send:

```php
use Illuminate\Contracts\Auth\MustVerifyEmail;

class User extends Authenticatable implements MustVerifyEmail
{
    //
}
```

Routes that require a verified user use the `verified` middleware. A guest is sent to login. A user who has not clicked the link is sent to the verification notice.

The resend button is a POST. The kit page already does this. If you are adding it to another page:

```ts
form.post("/email/verification-notification");
```

The link in the email is signed. Do not replace it with a Vue route that reads `?id=` and marks the user verified. That skips the hash Fortify checks.

## What to avoid

<Callout type="gotcha">

Do not log the verification URL. It signs the user in as verified when it is opened.


</Callout>
