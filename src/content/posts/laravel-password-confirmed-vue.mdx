People searching "Laravel password confirmation Vue" add one password input and then the rule fails with no obvious bug. `confirmed` looks for a second field named `{field}_confirmation`.

<TLDR audience="Laravel + Vue developers on Inertia" applies="Laravel 13 · Inertia 3 · Vue 3">

- The confirmed rule checks password_confirmation.
- The Vue form needs that second field name.
- Do not hash the password in the Vue page, and do not send a confirmation to a column.

</TLDR>

## The fix

Password reset on the starter kit already has both fields. The [Fortify guide](/laravel-fortify-vue) is that flow. This page is the rule when you add a password field of your own.

```php
use Illuminate\Validation\Rules\Password;

$validated = $request->validate([
    'password' => ['required', 'confirmed', Password::defaults()],
]);
```

```vue
<input v-model="form.password" name="password" type="password" autocomplete="new-password" />
<input v-model="form.password_confirmation" name="password_confirmation" type="password" autocomplete="new-password" />
<p v-if="form.errors.password">{{ form.errors.password }}</p>
```

The error is attached to `password`, not to `password_confirmation`. One paragraph under the first field is enough.

## What to avoid

<Callout type="gotcha">

Do not hash the password in the Vue page, and do not send a confirmation to a column. Only `password` is stored, and the cast on the User model hashes it. If you also `Hash::make()` in the controller, the password is hashed twice and login fails.


</Callout>
