You save a post, Laravel redirects to the list, and the list looks exactly like before. Did it work? Give the reader a one-time "Saved." toast with Inertia 3's flash data, and skip the session key the starter kit never reads.

<TLDR
  audience="Laravel + Vue developers on the Inertia 3 starter kit"
  learn={['How to flash a toast the starter kit already shows', 'Why `->with()` stays silent', 'How to show a flash line without the kit, and how to test it']}
  applies="Laravel 13 · Vue starter kit · inertia-laravel 3 · @inertiajs/vue3 3.9 · Pest"
>

- Call `Inertia::flash('toast', ['type' => 'success', 'message' => 'Saved.'])` before the redirect.
- The kit's `initializeFlashToast()` already displays it. Don't add another toast package.
- `->with('success', ...)` writes Laravel's session, which the kit's toast doesn't read.
- Test it with `assertInertiaFlash('toast.message', 'Saved.')`.

</TLDR>

The [CRUD guide](/laravel-inertia-vue-crud) saves a post and redirects to the list. The list looks the same as it did before the save. The reader has no signal that the write worked.

Inertia 3 has a flash for that. It lives for the next response, then it is gone. The back button does not bring it back, because it is not stored in the history entry. A row in the `notifications` table is a different feature, the [database bell](/laravel-vue-notifications). The stack is [Laravel and Vue in 2026](/laravel-vue-in-2026).

## On the Vue starter kit

The kit already listens. `resources/js/app.ts` calls `initializeFlashToast()`, and that function reads `flash.toast` and hands it to the toast that ships with the kit. Do not install another toast package. Do not register a second `router.on('flash')`.

Flash this shape before the redirect the CRUD `store` method already returns:

<CodeCompare before="Silent" after="Shows the toast">

```php title="app/Http/Controllers/PostController.php"
return to_route('posts.index')->with('success', 'Saved.');
```

```php title="app/Http/Controllers/PostController.php"
use Inertia\Inertia;

Inertia::flash('toast', [
    'type' => 'success',
    'message' => 'Saved.',
]);

return to_route('posts.index');
```

</CodeCompare>

`type` is `success`, `info`, `warning`, or `error`. The kit's profile controller uses the same array when it updates the account. Match it. A plain string under another key will not reach that listener.

<Callout type="gotcha" title="with() is a different flash">

A `with()` call on that redirect writes Laravel's session. The kit is not reading that key. The toast stays quiet.

</Callout>

## A line in the layout

Use this when the app does not call `initializeFlashToast()`. Flash a string and print it once. On the starter kit, prefer the `toast` array above so you do not show the same sentence twice.

```php title="app/Http/Controllers/PostController.php"
Inertia::flash('success', 'Saved.');

return to_route('posts.index');
```

```vue title="resources/js/layouts/AppLayout.vue"
<script setup lang="ts">
import { usePage } from "@inertiajs/vue3";

const page = usePage();
</script>

<template>
  <p v-if="page.flash.success">{{ page.flash.success }}</p>
  <slot />
</template>
```

<Callout type="tip" title="put it in the layout">

Put that `p` in the layout that wraps the pages, not in one form. The next visit clears it. You do not delete it yourself.

</Callout>

## A test

`assertInertiaFlash` reads the flash on the redirect. It does not need the Vue page to render.

```php title="tests/Feature/PostTest.php"
$this->post('/posts', [
    'title' => 'Hello Laravel 13',
    'excerpt' => 'A short excerpt.',
])->assertRedirect('/posts')
    ->assertInertiaFlash('toast.message', 'Saved.');
```

A banner that flashes `success` asserts that key with the same method. The rest of the create test stays in the CRUD guide.

<TryIt title="Run it">

```bash
php artisan test --filter=PostTest
```

</TryIt>

## back() or to_route()

Every Inertia form ends with a redirect, and the flash message travels with it. Choose the destination by what the user does next:

```php title="app/Http/Controllers/PostController.php"
public function publish(Post $post): RedirectResponse
{
    Gate::authorize('update', $post);
    $post->update(['published_at' => now()]);

    Inertia::flash('toast', ['type' => 'success', 'message' => 'Published.']);

    return back();                              // a row action: stay on the list
}

public function store(StorePostRequest $request): RedirectResponse
{
    $post = Post::create($request->validated());

    return to_route('posts.edit', $post);       // next step is the editor
}
```

`back()` uses the `Referer` header, falling back to the previous URL in the session. That suits list buttons and settings forms. `to_route()` is for a fixed destination. Don't return `response()->json(['ok' => true])` from an Inertia action and then navigate in `onSuccess`. Inertia expects a redirect or a page, so JSON isn't a valid response.

## Flash an error toast

The same toast handles failures. On the starter kit, the toast reads `flash.toast`, so an error is the same array with `type` set to `error`:

```php title="app/Http/Controllers/PostController.php"
use Inertia\Inertia;

try {
    $publisher->publish($post);
} catch (PublishFailed $e) {
    report($e);

    Inertia::flash('toast', [
        'type' => 'error',
        'message' => 'We could not publish that post. Try again in a minute.',
    ]);

    return back();
}
```

`type` is one of `success`, `info`, `warning` or `error`. A plain `->with('error', '...')` puts the string in the session under another key, so the kit's toast never sees it.

Use a toast for failures that aren't about a field, such as a timeout from a payment provider. A bad title still belongs in `form.errors.title` from `validate()`. If you show a toast and a field error for the same mistake, the user reads it twice.

<Callout type="gotcha" title="don't flash the exception message">

`$e->getMessage()` can contain SQL, file paths or provider details. Log the exception with `report($e)` and flash a sentence written for the person using the page.

</Callout>

## Recap

- Inertia flash data lives for one response and never comes back with the back button.
- On the starter kit, flash a `toast` array with `type` and `message`.
- `->with()` writes Laravel's session flash, a different channel.
- Assert it with `assertInertiaFlash`.
