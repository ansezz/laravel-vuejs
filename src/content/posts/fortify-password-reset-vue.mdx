People searching "Fortify password reset Vue" add a `PasswordResetController` beside the one Fortify registered. Turn the feature on and post to Fortify. The [Fortify guide](/laravel-fortify-vue) is the rest of the auth surface.

<TLDR audience="Laravel + Vue developers" applies="Laravel 13 · Vue 3">

- Fortify already exposes the forgot-password and reset-password URLs.
- The Vue form posts those fields and no others.
- Do not branch the Vue page on "we found that user".
- Do not put the new password in a query string, and do not email the new password back.

</TLDR>

## The fix

`config/fortify.php` needs `Features::resetPasswords()`. The kit pages live under `resources/js/pages/auth/`. The forgot form sends one field:

```ts
form.post("/forgot-password");
```

`form.email` is the only key. Fortify always responds as if the address might exist. Do not branch the Vue page on "we found that user".

The mail link opens the reset page with a token prop. That form posts:

```ts
form.token = token;
form.email = email;
form.post("/reset-password");
```

The fields are `token`, `email`, `password`, and `password_confirmation`. `form.errors.email` or `form.errors.password` is the failure. A 419 on this POST is the [session cookie](/laravel-sanctum-vue-spa), not a bad token.

## What to avoid
