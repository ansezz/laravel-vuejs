With soft deletes, Delete becomes an undo-able action. Laravel sets `deleted_at` instead of removing the row, and every normal query skips it. Then a few questions come up. Where do trashed rows show? How does the user restore one? When do they really go? This guide builds the whole loop for an Inertia app: the index, a trash screen, restore and force delete buttons, the policy methods, and pruning.

<TLDR audience="Laravel + Vue developers on Inertia" applies="Laravel 13 · Inertia 3 · Vue 3">

- `use SoftDeletes` plus a `softDeletes()` column. `delete()` sets `deleted_at`, and normal queries and route bindings skip the row.
- Trash screen: `Post::onlyTrashed()`. Restore route: `->withTrashed()` on that one route only.
- Policies have `restore` and `forceDelete` methods. Use them.
- Add `Prunable` with a `deleted_at` cutoff, and run `model:prune` from the scheduler.

</TLDR>

The model, query and route behaviour below runs in a Pest file on Laravel 13.39 with inertia-laravel 3.7.

## Turn it on

```php title="database/migrations/xxxx_add_deleted_at_to_posts.php"
Schema::table('posts', function (Blueprint $table) {
    $table->softDeletes();
});
```

```php title="app/Models/Post.php"
use Illuminate\Database\Eloquent\SoftDeletes;

class Post extends Model
{
    use SoftDeletes;
}
```

`$post->delete()` now sets `deleted_at`. In the test, after deleting one of two posts, `Post::count()` was 1, `withTrashed()->count()` was 2, and `onlyTrashed()` returned only the deleted one. The index needs no change: `Post::latest()->paginate(15)` already leaves trashed rows out. Don't pass trashed rows to the public index and hide them with `v-if`. They would still be in the page's JSON.

Unique indexes still see trashed rows. If a user deletes "hello-world" and then creates a new post with the same slug, the insert fails. The simplest fix is to treat slugs as unique across the trash too. Keep the plain `Rule::unique('posts', 'slug')`, so the user gets a validation message instead of a database error. Only use `Rule::unique(...)->withoutTrashed()` if the database index also ignores trashed rows.

## The trash screen

```php title="app/Http/Controllers/TrashController.php"
public function index(): Response
{
    Gate::authorize('viewAny', Post::class);

    return Inertia::render('posts/Trash', [
        'posts' => Post::onlyTrashed()
            ->latest('deleted_at')
            ->paginate(15)
            ->through(fn (Post $post) => [
                'id' => $post->id,
                'title' => $post->title,
                'deleted_at' => $post->deleted_at->diffForHumans(),
            ]),
    ]);
}
```

```vue title="resources/js/pages/posts/Trash.vue"
<script setup lang="ts">
import { router } from "@inertiajs/vue3";

defineProps<{ posts: { data: { id: number; title: string; deleted_at: string }[] } }>();

function restore(id: number) {
  router.post(`/posts/${id}/restore`, {}, { preserveScroll: true });
}

function destroyForever(id: number) {
  if (confirm("Delete this post forever? This cannot be undone.")) {
    router.delete(`/posts/${id}/force`, { preserveScroll: true });
  }
}
</script>

<template>
  <ul>
    <li v-for="post in posts.data" :key="post.id">
      {{ post.title }} · deleted {{ post.deleted_at }}
      <button type="button" @click="restore(post.id)">Restore</button>
      <button type="button" @click="destroyForever(post.id)">Delete forever</button>
    </li>
  </ul>
</template>
```

## Restore and force delete

A trashed post doesn't bind. In the test, `GET /posts/{id}/edit` for a trashed post was a 404. Opt in only on the routes that act on the trash:

```php title="routes/web.php"
Route::middleware('auth')->group(function () {
    Route::post('/posts/{post}/restore', [TrashController::class, 'restore'])->withTrashed()->name('posts.restore');
    Route::delete('/posts/{post}/force', [TrashController::class, 'destroy'])->withTrashed()->name('posts.force-delete');
});
```

```php title="app/Http/Controllers/TrashController.php"
public function restore(Post $post): RedirectResponse
{
    Gate::authorize('restore', $post);
    $post->restore();

    Inertia::flash('toast', ['type' => 'success', 'message' => "Restored \"{$post->title}\"."]);

    return back();
}

public function destroy(Post $post): RedirectResponse
{
    Gate::authorize('forceDelete', $post);
    $post->forceDelete();

    return back();
}
```

Don't put `withTrashed()` on the whole group. Edit and update would start opening deleted posts. A generated policy (`php artisan make:policy PostPolicy --model=Post`) already has `restore` and `forceDelete` methods. Restricting force delete to admins is a one-line change there. Keep the normal Delete button on `delete()`. Never wire the button labelled Delete to `forceDelete()`.

Soft deletes don't cascade. Comments on a trashed post are still live rows. Either soft delete them too, in a `deleted` model event, or filter them by their parent's state.

### Undo from a toast

The quickest restore is right after the delete. Have `destroy()` flash the post ID, and give the toast an Undo button that posts to `posts.restore`. It's the same route and the same policy check, with no trash screen needed.

## Prune old rows

Trash shouldn't grow forever. Make the model prunable:

```php title="app/Models/Post.php"
use Illuminate\Database\Eloquent\Prunable;

class Post extends Model
{
    use SoftDeletes, Prunable;

    public function prunable(): Builder
    {
        return static::onlyTrashed()->where('deleted_at', '<=', now()->subDays(30));
    }
}
```

```php title="routes/console.php"
Schedule::command('model:prune')->daily();
```

`model:prune` finds every model that uses `Prunable` and force deletes the matching rows. Deleting files or other cleanup goes in a `pruning()` method on the model. Run `php artisan model:prune --pretend` first to see how many rows it would remove.

## Test it

```php title="tests/Feature/TrashTest.php"
test('a trashed post leaves the index and comes back on restore', function () {
    $user = User::factory()->create(); // the policy allows restore for this user
    $post = Post::factory()->create();
    $post->delete();

    expect(Post::count())->toBe(0)->and(Post::onlyTrashed()->count())->toBe(1);
    $this->actingAs($user)->get("/posts/{$post->id}/edit")->assertNotFound();

    $this->actingAs($user)->from('/trash')->post("/posts/{$post->id}/restore")->assertRedirect('/trash');
    expect($post->fresh()->trashed())->toBeFalse();
});
```



## Recap

- Soft deleted rows disappear from queries and route bindings, so the index needs no changes.
- Trash: `onlyTrashed()`. Restore and force delete: `withTrashed()` on those routes only.
- Authorize with the policy's `restore` and `forceDelete`.
- Watch unique indexes and child rows. Prune with `Prunable` and `model:prune`.
