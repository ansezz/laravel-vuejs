Your Inertia page renders an empty list and the console is silent. The controller sent `posts.data`, the template looped over `posts`. One `defineProps` type turns that silent bug into a red line before you open the browser.

<TLDR
  audience="Laravel + Vue developers on the TypeScript starter kit"
  learn={['How to type an Inertia page with `defineProps`', 'The shape a Laravel paginator sends', 'Why dates arrive as strings', 'Where to keep the types']}
  applies="Laravel 13 · Vue starter kit · Vue 3.5 · TypeScript · vue-tsc"
>

- Type the props in the page with `defineProps<{ posts: Page }>()`, matching what the controller actually returns.
- A paginator wraps rows in `data`; loop over `posts.data`, not `posts`.
- Dates are JSON strings, so type them as `string | null`.
- Keep the interface next to the page; run the kit's `vue-tsc` check.

</TLDR>

The Vue starter kit is already TypeScript. The page is untyped until you say what the controller sends. `defineProps` on that single file is enough. You do not need a shared types package, and you do not need Vue Router. Routing stays in Laravel, which is the setup in [Inertia, a SPA, or Nuxt](/laravel-vue-in-2026).

The list this types is the [CRUD guide](/laravel-inertia-vue-crud). The first setup page returned `posts` as an array. The CRUD page wraps that array in `data`. Type the shape you actually return.

## The page

```vue title="resources/js/pages/posts/Index.vue" {4-20}
<script setup lang="ts">
import { Head, Link } from "@inertiajs/vue3";

interface Post {
  id: number;
  title: string;
  excerpt: string;
  published_at: string | null;
}

interface Page {
  data: Post[];
  current_page: number;
  last_page: number;
  prev_page_url: string | null;
  next_page_url: string | null;
}

defineProps<{
  posts: Page;
  filters: { search: string };
}>();
</script>

<template>
  <Head title="Posts" />
  <article v-for="post in posts.data" :key="post.id">
    <h2>{{ post.title }}</h2>
    <Link :href="`/posts/${post.id}/edit`">Edit</Link>
  </article>
</template>
```

<Callout type="gotcha" title="dates are strings">

`published_at` is a string in the props because Inertia serializes dates to JSON. Typing it as `Date` will not make it a `Date`. Format it as a string, or parse it on purpose.

</Callout>

## The posts.data trap

`posts.data` is the row list. `v-for="post in posts"` walks the paginator's values, the `data` array and then `current_page` and the rest, so `post.title` comes out blank. The key is the second alias, `(value, key)`. The type above makes that mistake a type error if you annotate the `v-for` source as `Post[]` and then pass `posts` instead of `posts.data`.

<CodeCompare before="Blank titles" after="Rows">

```vue title="resources/js/pages/posts/Index.vue"
<article v-for="post in posts" :key="post.id">
```

```vue title="resources/js/pages/posts/Index.vue"
<article v-for="post in posts.data" :key="post.id">
```

</CodeCompare>

### Paginator shapes differ

| Controller method | Has `last_page` and `total`? |
|---|---|
| `paginate()` | Yes |
| `simplePaginate()` | No |
| `cursorPaginate()` | No (cursor URLs instead) |

A simple paginator or a cursor paginator has no `last_page`. Drop that field from `Page` when the controller uses those methods. The differences are [pagination](/laravel-vue-pagination).

## What stays local

Keep this interface next to the page that receives it. A global `PageProps` augmentation is worth it later, when every page reads the same shared `auth` user. It is the wrong first step. One wrong global type then lies to every page.

Wayfinder types the URL you visit. It does not type these props. That generator is [Wayfinder](/laravel-wayfinder-vue).

## Run the check

Run the kit's TypeScript check. A fresh starter kit calls `vue-tsc`. The script name is whatever `package.json` already has. Do not add a second checker.

<TryIt title="Break it on purpose">

Change `posts.data` to `posts` in the template, then run the check:

```bash
npx vue-tsc --noEmit
```

Put it back and the error goes away.

</TryIt>

<Callout type="heads-up" title="no as any">

A red `posts.data` means the controller and the page disagree. Fix the one that is wrong. Do not silence it with `as any`.

</Callout>

## Where this stops

Component tests for a presentational child are [tests](/test-laravel-vue). They mount the child with a `title` string. They do not replace `defineProps` on the Inertia page.

## Recap

- `defineProps<...>()` on the page types the controller payload.
- Paginators wrap rows in `data`; simple and cursor paginators have no `last_page`.
- JSON dates are strings.
- Keep types local first; let `vue-tsc` catch disagreements.
