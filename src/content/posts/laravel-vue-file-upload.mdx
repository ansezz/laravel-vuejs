The upload "works", the database has a path, and the image is a broken icon. Or the file field is empty on every `PUT`. Uploading a cover image in Laravel + Vue is ordinary multipart, with three traps. Here is the full flow.

<TLDR
  audience="Laravel + Vue developers adding image uploads"
  learn={['How to store an upload on the public disk', 'How to send a file from the Inertia `<Form>`', 'How to replace old files and plan for production']}
  applies="Laravel 13 · Inertia 3 · Vue 3"
>

- Run `php artisan storage:link`, or saved files 404.
- Validate with `image` and `max:2048` (kilobytes), `store()` on the `public` disk, save the path.
- File + update: POST with `_method=put`; PHP does not fill files on a real PUT.
- Delete the old file when replacing; use S3-style storage with more than one server.

</TLDR>

A file input in an Inertia form is still a normal multipart request. Laravel validates it, stores it, and redirects back. You do not need a second upload library for a cover image on the [post form](/laravel-inertia-vue-crud).

## The column and the link

```bash
php artisan make:migration add_cover_path_to_posts_table --table=posts
php artisan storage:link
```

```php title="database/migrations/xxxx_add_cover_path_to_posts_table.php"
public function up(): void
{
    Schema::table('posts', function (Blueprint $table) {
        $table->string('cover_path')->nullable();
    });
}
```

<Callout type="gotcha" title="no link, no image">

Add `cover_path` to the model's `$fillable` array. `storage:link` points `public/storage` at `storage/app/public`, which is where the `public` disk writes. Without the link, the file saves and the `<img>` 404s.

</Callout>

## Validate and store

```php title="app/Http/Controllers/PostController.php"
public function update(Request $request, Post $post): RedirectResponse
{
    $data = $request->validate([
        'title' => ['required', 'string', 'max:255'],
        'excerpt' => ['required', 'string'],
        'cover' => ['nullable', 'image', 'max:2048'],
    ]);

    if ($request->hasFile('cover')) {
        $data['cover_path'] = $request->file('cover')->store('covers', 'public');
        unset($data['cover']);
    }

    $post->update($data);

    return to_route('posts.edit', $post);
}
```

<Callout type="heads-up" title="kilobytes, and paths not bytes">

`max:2048` is kilobytes, about 2 MB. `image` checks the content, not only the extension. `store()` returns a path like `covers/abc.jpg`. Save that path. Do not put the file bytes in the database.

</Callout>

Unset `cover` before `update()` so Eloquent does not try to write the uploaded file object into a string column.

Pass the current path to the page:

```php
'post' => $post->only(['id', 'title', 'excerpt', 'cover_path']),
```

## What the image rule accepts

`image` passes for jpg, jpeg, png, bmp, gif, webp, avif, heic and heif. SVG is excluded by default because it can carry scripts. If you really need it, use `image:allow_svg` and serve the file from somewhere that can't run it. For tighter control, list the types: `'mimes:jpg,png,webp'`.

`accept="image/*"` on the Vue input only filters the file picker. It isn't validation, and the rule on the server is still the check.

## When the file never reaches Laravel

`max:2048` is in kilobytes, so it means 2 MB. PHP has its own limits that apply first: `upload_max_filesize` (2M by default) and `post_max_size` (8M by default). If a file is over `upload_max_filesize`, PHP drops it before Laravel runs. The `cover` field then looks empty: `nullable` quietly passes, or `required` fails with a confusing message. If the whole body is over `post_max_size`, every field arrives empty.

Set both PHP limits above your Laravel rule, so the Laravel message is the one users see:

```ini title="php.ini"
upload_max_filesize = 10M
post_max_size = 12M
```

Write the rule in kilobytes and say what it means: `'max:5120'` is 5 MB. Don't write `max:5` with a comment that says 5 MB.

## The Vue form

<Callout type="gotcha" title="files and PUT">

The `<Form>` component from `@inertiajs/vue3` sends a file field as `multipart/form-data`. PHP does not fill that file on a real `PUT`, `PATCH`, or `DELETE`. Post the form and send `_method` of `put`, which is the spoof Laravel documents. Keep the `name` attribute. That is the key Laravel validates.

</Callout>

```vue title="resources/js/pages/posts/Edit.vue"
<script setup lang="ts">
import { Form } from "@inertiajs/vue3";

defineProps<{
  post: {
    id: number;
    title: string;
    excerpt: string;
    cover_path: string | null;
  };
}>();
</script>

<template>
  <Form
    :action="`/posts/${post.id}`"
    method="post"
    #default="{ errors, processing, progress }"
    class="space-y-4"
  >
    <input type="hidden" name="_method" value="put" />
    <input name="title" :defaultValue="post.title" />
    <p v-if="errors.title">{{ errors.title }}</p>

    <textarea name="excerpt" :defaultValue="post.excerpt" />
    <p v-if="errors.excerpt">{{ errors.excerpt }}</p>

    <img
      v-if="post.cover_path"
      :src="`/storage/${post.cover_path}`"
      alt=""
      class="max-h-40"
    />

    <input type="file" name="cover" accept="image/*" />
    <p v-if="errors.cover">{{ errors.cover }}</p>
    <progress v-if="progress" :value="progress.percentage" max="100" />

    <button :disabled="processing">Save</button>
  </Form>
</template>
```

`progress` is set while the body is uploading. `processing` stays true until Laravel responds. Disable the button for the whole request, not only while the bar moves.

<TryIt title="Upload something that isn't an image">

Rename a text file to `cover.jpg` and upload it. `image` checks the content, so you should see "The cover field must be an image" under the input, and nothing in `storage/app/public/covers`.

</TryIt>

A validation error for `cover` ("The cover field must be an image") comes back on the same page, the same way `errors.title` does in the CRUD guide.

## Replace and delete

`store()` does not remove the previous file. If the post already has a cover, delete it before saving the new one:

```php title="app/Http/Controllers/PostController.php"
use Illuminate\Support\Facades\Storage;

if ($request->hasFile('cover')) {
    if ($post->cover_path) {
        Storage::disk('public')->delete($post->cover_path);
    }

    $data['cover_path'] = $request->file('cover')->store('covers', 'public');
}
```

Do this in the same request as the database update. A queue is the wrong place for "the user just picked a new avatar" unless the file is large enough that the HTTP request times out.

## Production

The `public` disk is fine for images you are happy to serve from the app server. For anything private, use a non-public disk and a temporary URL. For more than one server, the local disk is the wrong place: the next request may hit a machine that does not have the file. Point the disk at S3-compatible storage then. The Vue form does not change.

| Where | Disk | `storage:link` |
|---|---|---|
| One server, public images | `public` | Once per machine |
| Private files | Non-public disk + temporary URL | n/a |
| Several servers | S3-compatible | n/a |
| Laravel Cloud | Attached bucket | Skip (disk resets) |

`php artisan storage:link` is once per machine when that machine serves the `public` disk. Laravel Cloud resets the app disk on each deploy, so do not rely on the symlink there. The [deploy guide](/deploy-laravel-vue) is the rest of that list. It will not create the `covers` directory for you. `store()` does that on first upload.

## Recap

- Link the storage once; save paths, not bytes.
- `image` + `max` in kilobytes on the server.
- Spoof `PUT` with `_method` when a file is attached.
- Clean up replaced files; move to object storage when you scale.
