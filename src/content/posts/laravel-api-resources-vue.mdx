Your Vue SPA calls `/api/posts`, logs the response, and the list is somehow on `response.data.data`. Or worse, a field you never meant to publish is in the JSON. API resources fix both: a fixed allow-list of keys and a predictable envelope.

<TLDR
  audience="Developers serving JSON to a Vue SPA or Nuxt"
  learn={['When you need a resource (and when Inertia does not)', 'How to shape one post and a paginated list', 'Why Axios rows are on `response.data.data`']}
  applies="Laravel 13 · Sanctum · Vue 3 · Axios"
>

- A resource is the allow-list of keys an HTTP client sees. Inertia pages can keep passing models.
- `PostResource::collection($paginator)` returns `{ data, links, meta }`.
- In Axios, `response.data.data` is the list: Axios envelope, then Laravel’s.
- Never put private file URLs or whole related models in a resource.

</TLDR>

An Inertia controller can return the `Post` model. The page receives props, not a JSON document you designed. A resource is for the other client: a Vue SPA or Nuxt that calls `/api/posts` and has to know the keys. That split is [Inertia, a SPA, or Nuxt](/laravel-vue-in-2026). The cookie on that request is [Sanctum](/laravel-sanctum-vue-spa). The Nuxt call is [Nuxt in front of the API](/nuxt-laravel-api).

## One post

```bash
php artisan make:resource PostResource
```

```php title="app/Http/Resources/PostResource.php"
public function toArray(Request $request): array
{
    return [
        'id' => $this->id,
        'title' => $this->title,
        'excerpt' => $this->excerpt,
        'published_at' => $this->published_at,
    ];
}
```

Those four keys match the `Post` from the [setup guide](/application-setup). Add a key here when the client needs it.

<CodeCompare before="Leaks whatever the model has" after="Only the keys you chose">

```php title="routes/api.php"
return Post::findOrFail($id);
```

```php title="routes/api.php"
return new PostResource(Post::findOrFail($id));
```

</CodeCompare>

<Callout type="gotcha" title="the resource is the allow-list">

Do not return the whole model and hope Vue ignores `remember_token` style extras later. A resource is the allow-list.

</Callout>

## A page of posts

`PostResource::collection` on a paginator keeps Laravel's `links` and `meta` and wraps each row.

```php title="routes/api.php"
Route::get('/posts', function () {
    $posts = Post::query()->latest('published_at')->paginate(10);

    return PostResource::collection($posts);
})->middleware('auth:sanctum');
```

The body is `{ data, links, meta }`. `data` is the ten posts. `links.next` and `meta.current_page` are the paginator. Vue code that treats the body as an array will render nothing.

```ts
const response = await axios.get("/api/posts");
const posts = response.data.data;
```

<Callout type="tip" title="the double data is expected">

`response.data` is the HTTP body. `response.data.data` is the list. The double `data` is Laravel's resource envelope, then Axios's envelope. It is not a bug in either one.

</Callout>

`meta.last_page` is present because this example uses `paginate(10)`. [Pagination](/laravel-vue-pagination) is what changes if you switch to `simplePaginate` or `cursorPaginate`. The resource does not add a total those paginators refused to count.

<TryIt title="Pin the envelope in a test">

```php title="tests/Feature/PostsApiTest.php"
it('returns a paginated resource', function () {
    Post::factory()->count(3)->create();

    $this->actingAs(User::factory()->create())
        ->getJson('/api/posts')
        ->assertOk()
        ->assertJsonStructure(['data' => [['id', 'title', 'excerpt', 'published_at']], 'links', 'meta']);
});
```

</TryIt>

## Format money on the server

Store integer cents. Format once on the server with `Number::currency`, and pass a string the page can print:

```php title="app/Http/Resources/OrderResource.php"
use Illuminate\Support\Number;

'price' => Number::currency($this->total_cents / 100, in: 'USD'),
```

In tests on Laravel 13, `Number::currency(1234.5, in: 'USD')` returns `$1,234.50`, and `Number::currency(1234.5, in: 'EUR', locale: 'de')` returns `1.234,50 €` (with a non-breaking space before the symbol). It needs the PHP `intl` extension, so a missing extension is a deploy problem, not a Vue problem.

Don't add two prices in the component with `+`. Binary floats make that wrong. Tax is another integer on the server. Don't use a `float` column for money, and don't send cents to the browser to format with string concatenation. Don't install a second currency package in the starter kit for one label.

## Format timestamps in the user's zone

Don't set `APP_TIMEZONE` to the signed-in user's city. That default is the app timezone, and every row would shift when someone else signs in. The database connection should store UTC. Convert for display in the resource:

```php title="app/Http/Resources/PostResource.php"
$zone = in_array($request->user()->timezone, timezone_identifiers_list(), true)
    ? $request->user()->timezone
    : config('app.timezone');

'createdAt' => $this->created_at->timezone($zone)->toIso8601String(),
```

A model's `toArray()` date is a UTC ISO string ending in `Z`. If you convert, do it once and let Vue print the string. Adding the offset again in the component is how a 10:00 post becomes 12:00. In tests on Laravel 13, `2026-11-10 02:00:00` UTC is `10:00` in `Asia/Kuala_Lumpur`.

Don't store a local datetime in a `timestamp` column by formatting it in PHP and writing the string. The next reader in another zone cannot undo a conversion you did not record. Don't trust a timezone name that is not in `timezone_identifiers_list()`.

## What not to put in the resource

Do not call `Storage::url` for a private file and hand the URL to any logged-in user. Public covers from the [upload guide](/laravel-vue-file-upload) can be a `/storage/...` path. Anything else stays behind a controller that checks the user.

Do not embed the entire author model. Pass `author: $this->user?->only(['id', 'name'])` when you add that relation. Until the post has a user, leave it out. The [policy guide](/laravel-vue-policies) is what adds `user_id`.

## Version the API under /api/v1

When a mobile app or a partner calls the same data, give the JSON API its own versioned prefix. Install the API routes with `php artisan install:api`, which also installs Sanctum. Then group the routes:

```php title="routes/api.php"
Route::prefix('v1')->middleware('auth:sanctum')->group(function () {
    Route::apiResource('posts', Api\V1\PostController::class)->only(['index', 'show']);
});
```

The URL is `/api/v1/posts`, because `routes/api.php` already adds `/api`. Keep the controllers and resources under `Api\V1` too. A breaking change to a field then becomes a `V2` resource, and old clients keep working. Your Inertia pages don't call these routes. They get props from `routes/web.php` controllers, and those can reuse the same resource classes. Don't point an Inertia `<Link>` at `/api/v1/...`: a JSON body isn't an Inertia response, so the visit fails.

## Where this stops

<Callout type="heads-up" title="one source per list">

Inertia pages should not fetch this endpoint to paint the list they already receive as props. Two sources for the same rows will drift. Use the resource when the client is actually an HTTP client.

</Callout>


## Recap

- Use a resource when the client is a real HTTP client.
- `toArray` is the allow-list; add keys deliberately.
- A paginated collection keeps `links` and `meta`; rows are on `data`.
- Private files and full related models stay out.
- Format money with `Number::currency` and pass a string; store integer cents.
- Store timestamps in UTC and convert once to an allow-listed user timezone.
