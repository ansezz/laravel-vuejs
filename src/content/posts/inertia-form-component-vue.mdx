Inertia 3 gives a Vue page two ways to send a form to Laravel: the `<Form>` component and the `useForm` helper. Both read Laravel's validation errors without a 422 handler, and both follow the redirect your controller returns. This guide covers the parts every form needs: errors under the field, a reset after it saves, the scroll position, upload progress, a draft that survives the back button, and the one-click buttons that don't need a form.

<TLDR audience="Laravel + Vue developers on Inertia" applies="Laravel 13 · Inertia 3.11 · Vue 3.5">

- Use `<Form>` when the fields can be plain inputs with a `name`. Use `useForm` when the script needs the values, such as a computed preview or a file picked in code.
- A failed `validate()` is a redirect back with the errors in the session. Inertia shares them as one string per field: `errors.title`, `form.errors.title`.
- `post`, `put`, `patch` and `delete` keep component state by default. They do not keep the scroll position unless you pass `preserveScroll`.
- Keep passwords out of history state with `dontRemember()`.

</TLDR>

The Vue files below type-check with `vue-tsc` against `@inertiajs/vue3` 3.11 and actions generated by Wayfinder 0.1.23. The Laravel side runs in a Pest test on Laravel 13.39 with inertia-laravel 3.7 (8 tests).

## Form component or useForm

| You need | Use |
| --- | --- |
| Inputs that post as they are | `<Form>` |
| The values in the script (a preview, a computed total) | `useForm` |
| A file chosen in code, or a field that is not an input | `useForm` |
| A button that posts nothing, such as Publish | `router.post` |

`<Form>` reads the inputs by their `name` when it submits, like a normal HTML form. A `v-model` without a `name` is not sent. `useForm` holds the data in a reactive object, so you bind with `v-model` and submit with `form.post(url)`.

## The Form component

The Vue starter kit binds the Wayfinder form object straight onto the component. Generate actions with `php artisan wayfinder:generate --with-form` and `.form()` returns `{ action, method }`:

```vue title="resources/js/pages/posts/Create.vue"
<script setup lang="ts">
import { Form } from "@inertiajs/vue3";
import PostController from "@/actions/App/Http/Controllers/PostController";
import InputError from "@/components/InputError.vue";
</script>

<template>
  <Form
    v-bind="PostController.store.form()"
    reset-on-success
    disable-while-processing
    :options="{ preserveScroll: 'errors' }"
    v-slot="{ errors, processing, recentlySuccessful }"
  >
    <label for="title">Title</label>
    <input id="title" name="title" />
    <InputError :message="errors.title" />

    <label for="body">Body</label>
    <textarea id="body" name="report[description]"></textarea>
    <InputError :message="errors['report.description']" />

    <label><input type="checkbox" name="featured" value="1" /> Featured</label>

    <button type="submit" :disabled="processing">Save</button>
    <p v-if="recentlySuccessful">Saved.</p>
  </Form>
</template>
```

Three details save time:

- Give a checkbox `value="1"`. Without it, a checked box posts `"on"`, which Laravel's `boolean` rule rejects.
- Nested names such as `report[description]` come back as dotted error keys: `errors['report.description']`.
- `disable-while-processing` adds the `inert` attribute to the form while the request runs, so a double click can't post twice.

If you pass a Wayfinder object to `:action`, don't add `method` as well. The object already carries it.

## Show validation errors under the field

Laravel does the work. A failed `validate()` or form request throws `ValidationException`. For an Inertia request, that becomes a 302 back to the page with the errors in the session. The Inertia middleware then shares them as the `errors` prop, keeping the first message for each field. The page never sees a 422, so don't write a `catch` for one. Don't return `response()->json(['errors' => ...], 422)` from an Inertia route either, because the page won't show it.

```php title="app/Http/Controllers/PostController.php"
public function store(Request $request)
{
    $validated = $request->validate([
        'title' => ['required', 'string', 'max:120'],
        'report.description' => ['required'],
    ]);

    Post::create($validated);

    return to_route('posts.index');
}
```

Save `$validated`, not `$request->all()`. `validated()` only returns the fields that have a rule, so an extra `is_admin` field in the request never reaches the model. For the rules themselves (form requests, unique emails, enums), see the [validation guide](/laravel-form-request-inertia).

### The starter kit's InputError

The kit ships `resources/js/components/InputError.vue`. It takes one `message` prop and hides itself when the prop is empty:

```vue title="resources/js/components/InputError.vue"
<script setup lang="ts">
defineProps<{
    message?: string;
}>();
</script>

<template>
    <div v-show="message">
        <p class="text-sm text-red-600 dark:text-red-500">
            {{ message }}
        </p>
    </div>
</template>
```

Pass `errors.title` or `form.errors.title` straight in. It is a string, not an array. If you need every message for a field, add `with-all-errors` to `<Form>` or call `.withAllErrors()` on `useForm`. Then render a list, because `InputError` only expects one. Don't run the shadcn-vue CLI to add another error component on top of the kit. You end up with two components doing the same job.

### Two forms on one page

When a page has two forms with the same field names, give each one an error bag. `<Form error-bag="createPost">` or `form.post(url, { errorBag: 'createPost' })` sends an `X-Inertia-Error-Bag` header. The errors then arrive as `errors.createPost.title`, so the other form stays clean.

## Reset after it saves

`<Form reset-on-success>` clears every field after a successful submit. `:reset-on-success="['title']"` clears only some of them. `set-defaults-on-success` keeps what was typed as the new baseline, which suits an edit form. With `useForm`, call `reset` in the callbacks:

```vue title="resources/js/pages/settings/Password.vue"
<script setup lang="ts">
import { useForm } from "@inertiajs/vue3";
import InputError from "@/components/InputError.vue";

const form = useForm("UpdatePassword", {
  current_password: "",
  password: "",
  password_confirmation: "",
}).dontRemember("current_password", "password", "password_confirmation");

function submit() {
  form.put("/settings/password", {
    preserveScroll: true,
    onSuccess: () => form.reset(),
    onError: () => form.reset("password", "password_confirmation"),
  });
}
</script>

<template>
  <form @submit.prevent="submit">
    <input v-model="form.current_password" type="password" autocomplete="current-password" />
    <InputError :message="form.errors.current_password" />
    <input v-model="form.password" type="password" autocomplete="new-password" />
    <InputError :message="form.errors.password" />
    <input v-model="form.password_confirmation" type="password" autocomplete="new-password" />
    <button type="submit" :disabled="form.processing">Update password</button>
  </form>
</template>
```

`onSuccess` runs when the response has no errors. Inertia decides that by checking `page.props.errors`, not the status code. `resetAndClearErrors()` resets fields and clears their messages in one call, which is handy for a Cancel button.

## Keep the page state and the scroll

### preserveState

Each visit renders a fresh page component, so local state such as an open dropdown or typed text is lost. `post`, `put`, `patch`, `delete` and `reload` set `preserveState: true` by default, which is why a failed submit keeps what the user typed. A `get` visit doesn't, so a search box needs it set:

```ts
router.get(index.url(), { search: filters.search }, { preserveState: true, replace: true });
```

`preserveState: 'errors'` keeps the state only when the response has validation errors. `replace: true` keeps every keystroke search out of the back-button history.

### preserveScroll

Inertia scrolls to the top after a visit, including a form post that redirects back. Pass `preserveScroll: true` for a row action on a long list, or `'errors'` to stay put only when validation fails. Use the `preserve-scroll` prop on `<Link>`. A real "next page" link should still start at the top.

If the page scrolls inside a `div` with `overflow-y: auto` rather than the window, add the `scroll-region` attribute to that element. Inertia then tracks and restores its position too.

## Show progress

Inertia shows an NProgress bar at the top for every visit, after a 250 ms delay. Configure it once:

```ts title="resources/js/app.ts"
createInertiaApp({
  progress: { delay: 250, color: "#4B5563", showSpinner: false },
  // ...
});
```

`progress: false` turns it off. Pass `showProgress: false` to a single visit, or use `:show-progress="false"` on `<Form>`. For a file, `form.progress.percentage` gives the upload percentage:

```vue title="resources/js/pages/settings/Avatar.vue"
<script setup lang="ts">
import { useForm } from "@inertiajs/vue3";

const form = useForm<{ avatar: File | null }>({ avatar: null });

function pick(event: Event) {
  form.avatar = (event.target as HTMLInputElement).files?.[0] ?? null;
}
</script>

<template>
  <form @submit.prevent="form.post('/settings/avatar')">
    <input type="file" accept="image/*" @change="pick" />
    <progress v-if="form.progress" :value="form.progress.percentage" max="100">
      {{ form.progress.percentage }}%
    </progress>
    <button type="submit" :disabled="form.processing">Upload</button>
  </form>
</template>
```

A file in the data makes Inertia send `FormData`. The [file upload guide](/laravel-vue-file-upload) covers the Laravel rules and storage.

## Remember a half-filled form

Back and forward restore a page from history state, but not your local component state. Give `useForm` a key as the first argument and Inertia stores the data and errors in history: `useForm("UpdatePassword", {...})`. Use ``useForm(`EditPost:${post.id}`, {...})`` when the same page edits different records. Always call `dontRemember()` for password fields. History state is not encrypted unless you turn on history encryption. Some browsers also show a save-password prompt when password values are written there.

For state that isn't a form, use `useRemember`:

```vue title="resources/js/pages/posts/Index.vue"
<script setup lang="ts">
import { reactive } from "vue";
import { Link, router, useRemember } from "@inertiajs/vue3";
import { index, publish } from "@/actions/App/Http/Controllers/PostController";

const props = defineProps<{ search: string; posts: { id: number; title: string }[] }>();

type Filters = { search: string; showArchived: boolean };

// A reactive() argument comes back reactive. A plain object comes back as a ref.
const filters = useRemember(
  reactive<Filters>({ search: props.search, showArchived: false }),
  "Posts/Index:filters",
) as Filters;

function runSearch() {
  router.get(index.url(), { search: filters.search }, { preserveState: true, replace: true });
}

function publishPost(id: number) {
  router.post(publish.url(id), {}, { preserveScroll: true });
}
</script>

<template>
  <input v-model="filters.search" name="search" @keyup.enter="runSearch" />
  <Link :href="index({ query: { search: 'draft' } })">Drafts</Link>
  <ul>
    <li v-for="post in props.posts" :key="post.id">
      {{ post.title }}
      <button type="button" @click="publishPost(post.id)">Publish</button>
    </li>
  </ul>
</template>
```

<Callout type="gotcha" title="useRemember returns a ref for a plain object">

In Inertia 3.11, `useRemember({ search: '' })` wraps a plain object in a `ref`. The template unwraps it, but in the script you need `filters.value.search`. Pass `reactive({...})` to get a reactive object back. A remembered value survives back and forward, not a reload. Put a filter that must survive a reload into the query string.

</Callout>

## A one-click action with router.post

A Publish or Archive button has no fields, so it doesn't need a form object. `router.post(url, data, options)` takes the body as the second argument; `{}` posts nothing. The Laravel route must still be `POST`, and the controller still checks the [policy](/laravel-vue-policies). Logout must also be a POST, so another site can't log your users out with an image tag. When the user types something that can fail validation, switch to `useForm` so `form.errors` exists. Otherwise you have to read `page.props.errors` by hand.

## Test it

The Laravel half is easy to lock down. This Pest test posts an empty title with Inertia headers, checks for the redirect, and reads the shared errors:

```php title="tests/Feature/PostFormTest.php"
test('a failed validate() is a redirect back, never a 422', function () {
    $version = $this->get('/posts/create')->viewData('page')['version'];
    $headers = ['X-Inertia' => 'true', 'X-Inertia-Version' => $version];

    $this->from('/posts/create')
        ->post('/posts', ['title' => ''], $headers)
        ->assertStatus(302)
        ->assertRedirect('/posts/create');

    $this->get('/posts/create', $headers)
        ->assertJsonPath('props.errors.title', 'The title field is required.');
});

test('an error bag nests the errors under its name', function () {
    $version = $this->get('/posts/create')->viewData('page')['version'];
    $headers = ['X-Inertia' => 'true', 'X-Inertia-Version' => $version, 'X-Inertia-Error-Bag' => 'createPost'];

    $this->from('/posts/create')->post('/posts', ['title' => ''], $headers);

    $this->get('/posts/create', $headers)
        ->assertJsonPath('props.errors.createPost.title', 'The title field is required.');
});
```

The second request has to send the bag header too. inertia-laravel only nests the errors when the request carries `X-Inertia-Error-Bag`, and the browser repeats Inertia's headers when it follows the redirect.



## Recap

- `<Form>` for plain inputs, `useForm` when the script needs the data, `router.post` for buttons.
- Errors are a redirect plus a shared prop, one string per field. Use error bags when two forms share field names.
- Non-GET visits keep state by default. Scroll needs `preserveScroll`, and nested scrollers need `scroll-region`.
- Key your `useForm` to survive the back button, and `dontRemember()` the passwords.
