Route model binding lets Laravel turn `/posts/15` into a `Post` before your controller runs. A missing row becomes a 404, so a Vue page never mounts without its data. This guide covers binding by id, binding by slug, scoping a child to its parent, sending a missing model somewhere useful, and rendering the 404 as a Vue page instead of Laravel's default HTML.

<TLDR audience="Laravel + Vue developers on Inertia" applies="Laravel 13 · inertia-laravel 3 · Vue 3">

- Type-hint the model and name the parameter the same: `{post}` and `Post $post`. Missing rows are a 404 before your code runs.
- `{post:slug}` binds by another column for one route. `getRouteKeyName()` changes it for every route.
- Add `scopeBindings()` to nested routes, or a comment ID from another post still resolves.
- Use `Inertia::handleExceptionsUsing()` to render 404s as a Vue page, with the real 404 status.

</TLDR>

Each behaviour below runs in a Pest file on Laravel 13.39 with inertia-laravel 3.7 (7 tests, 31 assertions).

## Bind by id

```php title="routes/web.php"
Route::get('/posts/{post}', [PostController::class, 'show'])->name('posts.show');
```

```php title="app/Http/Controllers/PostController.php"
public function show(Post $post): Response
{
    return Inertia::render('posts/Show', [
        'post' => $post->only('id', 'title', 'body'),
    ]);
}
```

`/posts/15` loads post 15. `/posts/99999` is a 404, and `show()` never runs. That is why the Vue page doesn't need a `v-if="post"` guard. Send `only()` the columns the page renders, or use an [API resource](/laravel-api-resources-vue): the whole model ends up in the page's JSON and HTML. If you aren't using a route parameter, `Post::findOrFail($id)` returns the same 404.

## Bind by slug

A public URL reads better as `/blog/hello-world`. Choose the column in the route:

```php title="routes/web.php"
Route::get('/blog/{post:slug}', [BlogController::class, 'show'])->name('blog.show');
```

Or change the default for the model, so every `{post}` binds by slug:

```php title="app/Models/Post.php"
public function getRouteKeyName(): string
{
    return 'slug';
}
```

Give `slug` a unique index. That index is what makes the binding mean exactly one row. Generate the slug once, when the post is created, and keep it when the title changes. Shared links and the URLs [Wayfinder](/laravel-wayfinder-vue) generates must keep working. If you do allow a slug to change, validate it with `Rule::unique('posts', 'slug')->ignore($post)` and 301 the old one. Don't bind by `title`: titles change and aren't unique.

The Vue side doesn't change. Wayfinder detects the binding key in the route, so `show(post.slug)` or `show({ slug: post.slug })` builds the right URL.

## Scope a child to its parent

```php title="routes/web.php"
Route::scopeBindings()->group(function () {
    Route::get('/posts/{post}/comments/{comment}', [CommentController::class, 'show']);
});
```

Without `scopeBindings()`, Laravel resolves `{comment}` by ID alone. In the test for this page, `/posts/1/comments/7` returned comment 7 even though it belonged to post 2. With scoping, Laravel looks the comment up through `$post->comments()`, and the same URL is a 404. Scoping is automatic when the child uses a custom key, as in `{comment:slug}`. Scoping isn't authorization: still check the [policy](/laravel-vue-policies) for what the user may do.

## When the model is missing

The 404 is usually right. For an old slug, a redirect is kinder:

```php title="routes/web.php"
Route::get('/blog/{post:slug}', [BlogController::class, 'show'])
    ->missing(fn (Request $request) => redirect()->route('blog.index', ['search' => $request->route('post')]));
```

The `missing` closure runs only when binding fails. Don't use it to hide every missing record behind a redirect to the index with a "not found" flash. Search engines and users both need the 404 for a page that really is gone.

## Render the 404 as a Vue page

During development, Inertia shows any non-Inertia response, including Laravel's 404 HTML, in a modal. In production, render your own page. inertia-laravel 3 has a hook for it:

```php title="app/Providers/AppServiceProvider.php"
use Inertia\ExceptionResponse;
use Inertia\Inertia;

public function boot(): void
{
    Inertia::handleExceptionsUsing(function (ExceptionResponse $response) {
        if (in_array($response->statusCode(), [403, 404, 500, 503])) {
            return $response->render('ErrorPage', ['status' => $response->statusCode()])
                ->withSharedData();
        }
    });
}
```

```vue title="resources/js/pages/ErrorPage.vue"
<script setup lang="ts">
import { computed } from "vue";

const props = defineProps<{ status: 403 | 404 | 500 | 503 }>();

const title = computed(() => ({
  403: "You can't open this page",
  404: "Page not found",
  500: "Something went wrong",
  503: "Back soon",
})[props.status]);
</script>

<template>
  <h1>{{ title }}</h1>
  <a href="/">Go home</a>
</template>
```

The response keeps its status. In the test, the Inertia request for a missing post returned `404` with component `ErrorPage` and `props.status` set to 404. `withSharedData()` adds your shared props, such as `auth`, because a binding failure happens outside the Inertia middleware. Leave `APP_DEBUG=true` locally to keep the stack trace modal. Don't catch the exception and return `Inertia::render('Errors/404')` from a controller: that sends a 200.

## Soft-deleted models

A model that uses `SoftDeletes` doesn't bind once it's trashed. Edit and show return 404. Opt a single route in with `->withTrashed()`, usually the restore route. The [soft deletes guide](/laravel-soft-deletes-index-vue) has the full trash screen.

## Test it

```php title="tests/Feature/PostBindingTest.php"
test('binds by slug and 404s for an unknown one', function () {
    $post = Post::factory()->create(['slug' => 'hello-world']);

    $this->get('/blog/hello-world')->assertOk();
    $this->get('/blog/nope')->assertNotFound();
});

test('a comment from another post does not resolve', function () {
    [$a, $b] = Post::factory()->count(2)->create();
    $comment = $b->comments()->create(['body' => 'on b']);

    $this->get("/posts/{$a->id}/comments/{$comment->id}")->assertNotFound();
    $this->get("/posts/{$b->id}/comments/{$comment->id}")->assertOk();
});
```



## Recap

- `{post}` plus `Post $post` gives you a model or a 404 before your code runs.
- `{post:slug}` for one route, `getRouteKeyName()` for all of them. Keep a unique index.
- `scopeBindings()` on nested routes.
- `missing()` for a useful redirect. `handleExceptionsUsing()` for a Vue 404 page that keeps the 404 status.
