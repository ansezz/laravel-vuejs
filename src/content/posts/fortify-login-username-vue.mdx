People searching "Fortify login username" rename the database column and leave the form posting `email`. Fortify reads the key in `config/fortify.php`.

<TLDR audience="Laravel + Vue developers" applies="Laravel 13 · Vue 3">

- Fortify's username config key is the input name.
- The Vue login form has to post that same name.
- Do not accept either email or username unless you wrote a custom user provider.

</TLDR>

## The fix

```php
'username' => 'email',
```

Change that to the column you actually look up, then match the Vue input:

```vue
<input v-model="form.email" name="email" type="email" autocomplete="username" />
```

If the config says `username`, the input `name` and the `useForm` key are `username`. The validation error comes back on that same key. The [Fortify guide](/laravel-fortify-vue) shows the POST to `/login` after the CSRF cookie, for a separate SPA. An Inertia kit posts `/login` on the same origin and does not need that cookie call.

## What to avoid

<Callout type="gotcha">

Do not accept either email or username unless you wrote a custom user provider. Changing the label on the page does not change the column Fortify queries.


</Callout>
