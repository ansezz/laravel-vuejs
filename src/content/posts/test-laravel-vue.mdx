Your Pest suite is green and the page still renders blank, or your Vue tests pass while the query is wrong. Each side needs its own test, and neither should pretend to be the other. Here is the split, plus the Vitest setup the starter kit doesn't include.

<TLDR
  audience="Laravel + Vue developers adding tests"
  learn={['What Pest covers and what Vitest covers', 'How to add Vitest to the starter kit', 'How to fake an outbound HTTP call with Http::fake()', 'What not to mock']}
  applies="Laravel 13 · Pest · Vitest · @vue/test-utils · Vue 3"
>

- Pest + `assertInertia`: routes, validation, queries and the props Inertia receives.
- Vitest + `@vue/test-utils`: markup that renders from props, with no server.
- The kit has no Vitest: install `vitest @vue/test-utils jsdom` and add `vitest.config.ts`.
- Don’t mount a page and stub Inertia’s router just to see a heading.
- Stub outbound HTTP with `Http::fake()` and `preventStrayRequests()` so the test never hits the real host.

</TLDR>

A Laravel and Vue app has two test runs because the two sides fail differently. Pest can prove a POST creates a row and that Inertia received `posts.data`. It does not mount the Vue page. Vitest can prove a component renders a title from a prop. It does not hit SQLite. [The requirements](/requirements) name both Pest and Vitest. This page is how to add the Vue half without pretending the starter kit already has it.

| | Pest (PHP) | Vitest (JS) |
|---|---|---|
| Proves | A POST creates a row; Inertia got `posts.data` | A component renders a title from a prop |
| Does not | Mount the Vue page | Hit SQLite |

## Feature tests first

The feature tests for create, an empty title, and search are already in the [CRUD guide](/laravel-inertia-vue-crud). Run those first.

```bash
php artisan test --filter=PostsTest
```

Feature tests use the session stack. They do not need a CSRF token. `assertInertia` reads the props the controller returned. If `posts.data` is missing, the controller is still returning a plain array, which is the bug the CRUD page calls out.

## A component test

<Callout type="heads-up" title="Vitest is not in the kit">

Do not claim the kit's `package.json` already has Vitest. Add it.

</Callout>

```bash
npm install -D vitest @vue/test-utils jsdom
```

```ts title="vitest.config.ts"
import { defineConfig } from "vitest/config";
import vue from "@vitejs/plugin-vue";

export default defineConfig({
  plugins: [vue()],
  test: {
    environment: "jsdom",
  },
});
```

Keep this file next to the kit's `vite.config.ts`. A component test should not boot Inertia's router. Pass props and read the text.

```vue title="resources/js/components/PostTitle.vue"
<script setup lang="ts">
defineProps<{ title: string }>();
</script>

<template>
  <h2>{{ title }}</h2>
</template>
```

```ts title="resources/js/components/PostTitle.test.ts"
import { mount } from "@vue/test-utils";
import { describe, expect, it } from "vitest";
import PostTitle from "./PostTitle.vue";

describe("PostTitle", () => {
  it("renders the title", () => {
    const wrapper = mount(PostTitle, {
      props: { title: "Hello Laravel 13" },
    });

    expect(wrapper.text()).toContain("Hello Laravel 13");
  });
});
```

```json title="package.json"
{
  "scripts": {
    "test:unit": "vitest run"
  }
}
```

<TryIt title="Run the first component test">

```bash
npm run test:unit
```

</TryIt>

<Callout type="gotcha" title="window at import time">

`jsdom` is there so `mount` has a document. If the component reads `window` at import time, the test fails the same way [server rendering](/inertia-ssr) fails. Move that read into `onMounted`, or pass the value in as a prop.

</Callout>

## What not to mock

<Callout type="gotcha" title="brittle page mocks">

Do not mount `posts/Index.vue` and stub `router.get` just to see a heading. That test breaks every time Inertia's API moves, and it never notices a wrong SQL `when`. The Pest test owns the query. The Vitest test owns markup that has no server.

</Callout>

Typed props for the page itself are [TypeScript on Vue pages](/typescript-laravel-vue-pages). The stack you are testing is [Inertia, a SPA, or Nuxt](/laravel-vue-in-2026).

## Fake an HTTP call

When a page's props come from an outbound HTTP call, the Pest test should not hit the real host. `Http::fake()` stubs the client. `assertInertia` still checks the prop.

```php title="tests/Feature/CreatePostTest.php"
use Illuminate\Support\Facades\Http;
use Inertia\Testing\AssertableInertia as Assert;

Http::preventStrayRequests();

Http::fake([
    'https://maps.example/*' => Http::response(['label' => 'Rabat'], 200),
]);

$this->actingAs($user)
    ->get('/posts/create')
    ->assertOk()
    ->assertInertia(fn (Assert $page) => $page
        ->component('posts/Create')
        ->where('label', 'Rabat')
    );
```

The controller calls `Http::get('https://maps.example/place')` and passes `label` as a prop. The test never opens a socket. `preventStrayRequests()` fails the test when a URL is not faked, instead of silently calling the network. In the lab (Laravel 13.40, 8 tests), a matching pattern returned `Rabat`, and a request to another host threw `Illuminate\Http\Client\StrayRequestException`.

You can also return a sequence for the same pattern, which is how you test a retry after a 429:

```php
Http::fake([
    'https://maps.example/*' => Http::sequence()
        ->push(['label' => 'Rabat'], 200)
        ->pushStatus(429),
]);
```

The [queue 429 guide](/laravel-queue-429-rate-limited-api) is the job side of that retry.

<Callout type="gotcha" title="an empty fake is not your API">

Do not call `Http::fake()` with no arguments and then assert the prop equals the real city's name. An empty fake returns 200 and an empty body. I confirmed that in the lab: `Http::fake()` then `Http::get(...)` was 200 with `''`. Do not disable TLS verification so the test can "just hit staging".

</Callout>

If the pattern does not match and you did not call `preventStrayRequests()`, Laravel will make the real request. That is the usual reason a "faked" test still hits the provider.

## Recap

- Two runners, two jobs: Pest for the server, Vitest for components.
- Add Vitest yourself; the kit does not ship it.
- Component tests pass props, not routers.
- Keep queries tested in Pest.
- Stub outbound HTTP with `Http::fake()` and `preventStrayRequests()`. Assert the Inertia prop, not the real API.
