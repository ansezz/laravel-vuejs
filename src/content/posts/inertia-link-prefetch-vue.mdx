People searching "Inertia prefetch" put `prefetch` on every link, including ones that post. Prefetch sends a GET. Use it for a page the user is about to open.

<TLDR audience="Laravel + Vue developers on Inertia" applies="Laravel 13 · Inertia 3 · Vue 3">

- prefetch on a Link loads a GET page before the click.
- Do not prefetch a POST, a logout, or a page the user cannot open.
- Do not prefetch a logout URL.
- Do not prefetch a URL the [policy](/laravel-vue-policies) will reject.

</TLDR>

## The fix

```vue
<script setup lang="ts">
import { Link } from "@inertiajs/vue3";
</script>

<template>
  <Link href="/posts" prefetch>Posts</Link>
</template>
```

The default waits for a hover. The next click is faster because the response is already in memory. The [pagination guide](/laravel-vue-pagination) is the list this link usually opens. Prefetch does not change that page's props.

## What to avoid

<Callout type="gotcha">

Do not prefetch a logout URL. Logout is a POST, and a GET prefetch would either fail or, worse, hit a route you mistakenly registered as GET. Do not prefetch a URL the [policy](/laravel-vue-policies) will reject. You would be caching a 403 for a hover.

</Callout>

Do not prefetch a page that runs a write in its controller. A controller that writes on GET is already a bug. Prefetch makes it happen on hover.
