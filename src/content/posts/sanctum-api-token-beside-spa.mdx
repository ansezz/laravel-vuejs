People searching "Sanctum API token Vue" store a bearer token in the Inertia app. Sanctum's own guidance, written up in the [Sanctum guide](/laravel-sanctum-vue-spa), is that your own SPA uses the session cookie. A token is for a client that cannot use that cookie.

<TLDR audience="Laravel + Vue developers" applies="Laravel 13 · Vue 3 · Sanctum">

- A first-party Vue SPA uses the session cookie.
- createToken is for a mobile client or another product.
- Do not put the token in `localStorage` on the Vue starter kit, and do not send `Authorization: Bearer` from an Inertia form.

</TLDR>

## The fix

The user model uses Sanctum's trait, not Passport's. The [Passport comparison](/laravel-sanctum-vs-passport) is why those two traits do not stack.

```php
use Laravel\Sanctum\HasApiTokens;

class User extends Authenticatable
{
    use HasApiTokens;
}
```

Issue a token from a route the mobile client calls after it has authenticated. Return the plain text once:

```php
$token = $request->user()->createToken('phone')->plainTextToken;

return response()->json(['token' => $token]);
```

The Inertia pages keep using `auth` and the session. They never read this JSON.

## What to avoid

<Callout type="gotcha">

Do not put the token in `localStorage` on the Vue starter kit, and do not send `Authorization: Bearer` from an Inertia form. You would be maintaining two logins for one browser.


</Callout>
