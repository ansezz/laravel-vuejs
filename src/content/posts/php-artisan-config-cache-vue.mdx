People searching "Laravel env returns null" call `env('APP_NAME')` in a controller after production cached the config. `php artisan config:cache` bakes `config/*.php` into one file and stops reading `.env` on each request. `env()` outside those config files is null. The [deploy guide](/deploy-laravel-vue) is where the cache is built.

<TLDR audience="Laravel + Vue developers" applies="Laravel 13 · Vue 3">

- After config:cache, read config('app.name').
- env() outside config files returns null.
- Do not call `env()` in a Vue prop "just this once".
- Do not cache config in local development and then wonder why `.env` edits do nothing.

</TLDR>

## The fix

```php
$name = config('app.name');
```

Put a new key in a config file first:

```php title="config/services.php"
'maps_key' => env('MAPS_KEY'),
```

Then read `config('services.maps_key')`. Change `.env`, then rebuild the cache. Editing `.env` alone does nothing while the cache exists.

## What to avoid

<Callout type="gotcha">

Do not call `env()` in a Vue prop "just this once". Do not cache config in local development and then wonder why `.env` edits do nothing. Local should stay uncached. `php artisan config:clear` drops the cache.


</Callout>
