You want an AI-drafted reply on a page you already have, without leaking the provider key or building a chat app. The Laravel AI SDK does it in one agent class, one controller action and one Inertia form, and Pest can fake it.

<TLDR
  audience="Laravel + Vue developers adding a first AI feature"
  learn={['How to install the Laravel AI SDK and set a provider key', 'How to write a small agent and prompt it from a controller', 'How to show the reply on an Inertia page and fake it in Pest']}
  applies="Laravel 13 · laravel/ai · Inertia 3 · Vue 3 · Pest"
>

- `composer require laravel/ai`, publish, set **one** provider key in `.env`.
- `make:agent DraftReply`; prompt it from an authenticated controller with only the validated note.
- Redirect back with `(string) $draft`; the Vue page renders it as a prop.
- `DraftReply::fake([...])` + `assertPrompted()` in tests; no real provider calls.

</TLDR>

People searching "Laravel AI SDK" and "Laravel AI Vue" want a reply on a page they already have. The [Laravel AI SDK](https://laravel.com/framework/docs/13.x/ai-sdk) is the official package for that. It talks to OpenAI, Anthropic, Gemini, and the other supported providers through one PHP API. The Vue page only sends the note and renders the text that comes back.

<Callout type="gotcha" title="the key never reaches Vue">

Do not call the provider from the browser. A `VITE_` variable is shipped to every visitor. Put the key in `.env` and prompt from a controller.

</Callout>

## Install the SDK

```shell
composer require laravel/ai
php artisan vendor:publish --provider="Laravel\Ai\AiServiceProvider"
php artisan migrate
```

Publishing writes `config/ai.php` and the conversation migrations. The migrate step creates `agent_conversations` and `agent_conversation_messages`. You need those tables only when an agent stores a thread. A one-shot reply does not.

Set one provider key. The SDK reads it from the environment:

```ini title=".env"
ANTHROPIC_API_KEY=
OPENAI_API_KEY=
GEMINI_API_KEY=
```

Leave the keys you do not use empty. Do not copy a key into `resources/js`.

## One agent, one job

`php artisan make:agent DraftReply` creates `app/Ai/Agents/DraftReply.php`. Keep the first agent small. This one rewrites a note. It does not browse, store a thread, or pick a model per request.

```php title="app/Ai/Agents/DraftReply.php"
<?php

namespace App\Ai\Agents;

use Laravel\Ai\Contracts\Agent;
use Laravel\Ai\Promptable;

class DraftReply implements Agent
{
    use Promptable;

    public function instructions(): string
    {
        return 'Rewrite the note as one short reply. Do not add facts that are not in the note.';
    }
}
```

Prompt it from a controller that already belongs to the page. Validate the note. Cast the response to a string, which the docs do for a text agent. Send the visitor back to the form with that string in the session.

```php title="app/Http/Controllers/ReplyController.php"
public function create(): Response
{
    return Inertia::render('replies/Create', [
        'draft' => session('draft'),
    ]);
}

public function store(Request $request): RedirectResponse
{
    $validated = $request->validate([
        'note' => ['required', 'string', 'max:2000'],
    ]);

    $draft = (new DraftReply)->prompt($validated['note']);

    return to_route('replies.create')->with('draft', (string) $draft);
}
```

<Callout type="gotcha" title="an open prompt endpoint is an open bill">

Put both routes behind `auth`. An open prompt endpoint is an open bill. Do not pass `$request->all()` into `prompt()`. The agent should see the note, not the rest of the request.

</Callout>

`prompt()` accepts a provider and a model when you need to override the default:

```php
use Laravel\Ai\Enums\Lab;

$draft = (new DraftReply)->prompt(
    $validated['note'],
    provider: Lab::Anthropic, // [!code highlight]
    timeout: 120,
);
```

## Show it on the Vue page

The page is a normal Inertia form. `useForm` posts the note. The draft arrives as a prop after the redirect. Validation errors land on `form.errors.note` because the controller used `$request->validate()`.

```vue title="resources/js/pages/replies/Create.vue"
<script setup>
import { useForm } from "@inertiajs/vue3";

defineProps({
  draft: { type: String, default: "" },
});

const form = useForm({ note: "" });

function submit() {
  form.post("/replies");
}
</script>

<template>
  <form @submit.prevent="submit">
    <textarea v-model="form.note" name="note" maxlength="2000" />
    <p v-if="form.errors.note">{{ form.errors.note }}</p>
    <button type="submit" :disabled="form.processing">Draft a reply</button>
    <p v-if="draft">{{ draft }}</p>
  </form>
</template>
```

<Callout type="heads-up" title="redirect first, stream later">

Do not install a second HTTP client for this form. Inertia already posts it. A streamed reply is a different endpoint: `stream()` can be returned from a route and Laravel sends server-sent events. That is not an Inertia visit. Ship the redirect first.

</Callout>

## Fake the agent in a test

<TryIt title="Run it without spending a token">

`DraftReply::fake()` stops the test from calling a provider. Pass the replies in order. `assertPrompted` checks the note that crossed the wire.

```php title="tests/Feature/DraftReplyTest.php"
use App\Ai\Agents\DraftReply;
use App\Models\User;

it('shows the drafted reply', function () {
    DraftReply::fake(['The invoice is three days late.']);

    $this->actingAs(User::factory()->create())
        ->post('/replies', ['note' => 'Invoice late by 3 days'])
        ->assertRedirect()
        ->assertSessionHas('draft', 'The invoice is three days late.');

    DraftReply::assertPrompted('Invoice late by 3 days');
});
```

`php artisan test --filter=DraftReply` passes with no provider key set.

</TryIt>

A closure receives the `AgentPrompt` when the reply depends on the note. `preventStrayPrompts()` fails the test if something prompts an agent you did not fake.

## What to leave out

<Callout type="gotcha" title="continue() does not check ownership">

Do not store a conversation until a person needs the previous turn. `RemembersConversations` writes the thread, and `forUser($user)` starts one. `continue($id, as: $user)` resumes it. Before you continue an id that came from the browser, check `conversationBelongsTo()` on the conversation store. The docs say `continue` does not check ownership.

</Callout>

Do not add tools, structured output, or a second provider on the first page. A structured agent implements `HasStructuredOutput` and a `schema()` method, then the response is read like an array. That is the next change, after this page returns a string.

The stack choice for the page itself is still the one in [Laravel and Vue in 2026](/laravel-vue-in-2026). The form posts like the [CRUD guide](/laravel-inertia-vue-crud). The test style matches [Test a Laravel and Vue app](/test-laravel-vue).

## Structured output instead of parsing text

When the page needs fields, not prose, have the agent return a schema. Implement `HasStructuredOutput` and the response becomes array-accessible:

```php title="app/Ai/Agents/ScoreNote.php"
use Illuminate\Contracts\JsonSchema\JsonSchema;
use Laravel\Ai\Contracts\Agent;
use Laravel\Ai\Contracts\HasStructuredOutput;
use Laravel\Ai\Promptable;

class ScoreNote implements Agent, HasStructuredOutput
{
    use Promptable;

    public function instructions(): string
    {
        return 'Score the note from 1 to 5 and give one reason.';
    }

    public function schema(JsonSchema $schema): array
    {
        return [
            'score' => $schema->integer()->min(1)->max(5)->required(),
            'reason' => $schema->string()->required(),
        ];
    }
}
```

```php
$response = (new ScoreNote)->prompt($validated['note']);

return Inertia::render('notes/Show', [
    'score' => $response['score'],
    'reason' => $response['reason'],
]);
```

The Vue page gets two plain props and never parses JSON. Pass only the validated field to `prompt()`, not `$request->all()`. The AI SDK 1.3 release added typed classes for this: see [typed structured output](/laravel-ai-sdk-1-3-typed-structured-output-file-limits).

## Stream a reply to Vue

`stream()` returns a streamed response of server-sent events. Give it its own route, because it isn't an Inertia visit:

```php title="routes/web.php"
Route::post('/replies/stream', function (Request $request) {
    $validated = $request->validate(['note' => ['required', 'string', 'max:2000']]);

    return (new DraftReply)->stream($validated['note']);
})->middleware(['auth', 'throttle:20,1']);
```

On the Vue side, start it with `fetch` and read `response.body` as a stream, not with `useForm` or `<Form>`. Those wait for an Inertia page or a redirect and won't render tokens as they arrive. Keep `auth` and a throttle on the route: an open streaming endpoint is an open bill with your provider. Validation errors here come back as a normal 422 JSON response, so your fetch code has to read them.

## Continue a conversation the user owns

`RemembersConversations` stores each exchange in the `agent_conversations` and `agent_conversation_messages` tables, so publish and run the SDK migrations first:

```php
use Laravel\Ai\Concerns\RemembersConversations;
use Laravel\Ai\Contracts\Conversational;

class DraftReply implements Agent, Conversational
{
    use Promptable, RemembersConversations;
}
```

Don't define your own `messages()` on that class, or the stored thread is ignored. Start a thread for the user, then send `conversationId` to the page:

```php
$reply = (new DraftReply)->forUser($request->user())->prompt($validated['note']);
// $reply->conversationId
```

`continue()` doesn't check who owns the id, and the id comes back from the browser. Check ownership before you continue:

```php
use Laravel\Ai\Contracts\ConversationStore;

abort_unless(app(ConversationStore::class)->conversationBelongsTo(
    $validated['conversation'],
    $request->user()->getMorphClass(),
    $request->user()->getKey(),
), 403);

$reply = (new DraftReply)
    ->continue($validated['conversation'], as: $request->user())
    ->prompt($validated['note']);
```

Render stored messages as text, never with `v-html`.

## Tool approval pauses the agent

A tool that needs approval stops the run. The response tells you, and the page asks the user:

```php
if ($response->hasPendingApprovals()) {
    return Inertia::render('notes/Approve', [
        'conversation' => $response->conversationId,
        'pending' => $response->pendingApprovals,
    ]);
}
```

Resuming needs the stored conversation, so this only works with `RemembersConversations`: a one-shot `prompt()` has nothing to resume. Check ownership as above, then continue with a decision for each pending call:

```php
use Laravel\Ai\Approvals\Decision;
use Laravel\Ai\Approvals\Decisions;

$response = (new DraftReply)
    ->continue($validated['conversation'], as: $request->user())
    ->prompt(Decisions::from([
        $validated['call_id'] => Decision::approve(),
    ]));
```

Don't auto-approve inside the tool to make a demo work. That removes the reason the approval exists. The [1.1 and 1.2 release notes](/laravel-ai-sdk-1-2-skills-approval-cohere) cover the approval API in more depth.

### More test assertions

`DraftReply::fake([...])` returns canned responses in order, so no request reaches the provider. Two more helpers keep tests honest:

```php
DraftReply::fake(['Rewritten.'])->preventStrayPrompts();

$this->actingAs($user)->post('/replies', ['note' => 'Ship the form.'])->assertRedirect();

DraftReply::assertPrompted('Ship the form.');
```

`assertPrompted` fails if the controller sent `$request->all()` or an empty string. `preventStrayPrompts()` fails the test if the agent is prompted more times than you faked. Don't keep a real key in `.env.testing` "just for one test": it costs money and makes the suite flaky.

## Recap

- Key in `.env`, agent in PHP, reply as a prop.
- Validate and authenticate before you prompt.
- Pass only the validated note to `prompt()`.
- Fake every agent in tests; add tools, threads and streams later.
