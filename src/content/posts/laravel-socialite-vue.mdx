"Continue with GitHub" looks like one button. Wire it to `axios.get` and nothing happens; reset a password on every login and someone loses theirs. Here is the whole flow in two routes and a link, with the three traps marked.

<TLDR
  audience="Laravel + Vue developers adding GitHub login"
  learn={['How to configure Socialite for GitHub', 'The redirect and callback routes', 'How to match and create users safely']}
  applies="Laravel 13 · Socialite · Vue starter kit"
>

- The GitHub button is a plain `<a href>`, never an XHR.
- Credentials live in `config/services.php`, read from `.env`.
- Match users on email with `firstOrNew`; set a random password only when creating.
- If GitHub returns no email, do not create a user.

</TLDR>

Socialite sends the browser to GitHub and back. It is not an XHR. A Vue click handler that `axios.get`s the redirect URL will not follow GitHub's login page. The control is a normal link. The session it creates is still Laravel's session, which is the same cookie story as [Sanctum for a Vue SPA](/laravel-sanctum-vue-spa) when the front end is another origin. On the Inertia starter kit the link can live on the existing login page. The architecture is [Inertia, a SPA, or Nuxt](/laravel-vue-in-2026).

## Install

```bash
composer require laravel/socialite
```

The client id and secret come from the environment, through `config/services.php`. Do not read `env()` in the controller.

```php title="config/services.php"
'github' => [
    'client_id' => env('GITHUB_CLIENT_ID'),
    'client_secret' => env('GITHUB_CLIENT_SECRET'),
    'redirect' => env('GITHUB_REDIRECT_URI'),
],
```

`GITHUB_REDIRECT_URI` is the callback you register at GitHub, such as `http://localhost:8000/auth/github/callback`. The Inertia app served by Sail is `http://localhost` instead. Use the host the browser actually returns to.

## Two routes and a link

```php title="routes/web.php"
use App\Models\User;
use Illuminate\Support\Facades\Auth;
use Illuminate\Support\Facades\Hash;
use Laravel\Socialite\Facades\Socialite;

Route::get('/auth/github/redirect', function () {
    return Socialite::driver('github')->redirect();
});

Route::get('/auth/github/callback', function () {
    $githubUser = Socialite::driver('github')->user();

    $user = User::query()->firstOrNew([
        'email' => $githubUser->getEmail(),
    ]);

    $user->name = $githubUser->getName() ?: $githubUser->getNickname();

    if (! $user->exists) {
        $user->password = Hash::make(str()->random(40));
    }

    $user->save();

    Auth::login($user);

    return redirect('/dashboard');
});
```

```vue title="resources/js/pages/auth/Login.vue"
<a href="/auth/github/redirect">Continue with GitHub</a>
```

<CodeCompare before="Resets the password on every login" after="Password only on create">

```php title="routes/web.php"
$user = User::updateOrCreate(
    ['email' => $githubUser->getEmail()],
    ['name' => $githubUser->getName(), 'password' => Hash::make(str()->random(40))],
);
```

```php title="routes/web.php"
$user = User::query()->firstOrNew(['email' => $githubUser->getEmail()]);
$user->name = $githubUser->getName() ?: $githubUser->getNickname();
if (! $user->exists) {
    $user->password = Hash::make(str()->random(40));
}
$user->save();
```

</CodeCompare>

Match on email. Put the random password on the create path only. `updateOrCreate` with a new password in the second array resets that password on every GitHub login, including for someone who already had one.

<Callout type="gotcha" title="no email from GitHub">

GitHub does not always return an email. If `getEmail()` is null, do not insert a user with an empty email. Ask them to make the email visible on GitHub, or store the GitHub id and collect an email yourself. This callback does not invent a second account-linking flow.

</Callout>

The users table from the starter kit requires `password`. The random string satisfies that column. The person signs in through GitHub, not by typing it.

<TryIt title="Run the round trip">

1. Create an OAuth app at GitHub with the callback URL from `GITHUB_REDIRECT_URI`.
2. Put the id and secret in `.env`, then `php artisan config:clear`.
3. Click **Continue with GitHub**, approve, and land on `/dashboard` logged in.

</TryIt>

## Where this stops

Socialite does not replace Fortify's password reset. Email and password stay [Fortify](/laravel-fortify-vue). The callback above does not check a [permission](/laravel-vue-policies#roles-and-permissions-with-spatie). A new GitHub user is a normal user until you give them one.

Add scopes only when you need an API GitHub will not return by default. The login above uses the default user. Extra scopes are a decision you can point at the [Socialite docs](https://laravel.com/framework/docs/13.x/socialite), not a list to paste in before the first redirect works.

## Recap

- Socialite is a full-page redirect; use a link.
- Config in `services.php`, secrets in `.env`.
- `firstOrNew` on email; password on create only.
- Handle a missing email instead of inserting a blank one.
