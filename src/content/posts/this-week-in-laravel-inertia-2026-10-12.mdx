## Inertia 2.3.29: security backports for the 2.x line

If you haven't moved to Inertia 3 yet, this one is for you. It brings two fixes from 3.x back to 2.x.

**A unique IV for every encrypted history entry.** With history encryption on, Inertia encrypts page data in the browser's history with AES-GCM. Until now every entry shared one IV (the random value that keeps two encryptions of similar data from looking alike), generated once per tab and kept in `sessionStorage`. Now each entry gets a fresh IV, stored in front of its ciphertext.

**The prefetch cache is flushed on `clearHistory`.** When you clear history (for example on logout), prefetched pages are now dropped too, so a cached response can't outlive the session that fetched it.

```php title="app/Http/Controllers/Auth/LogoutController.php"
use Inertia\Inertia;

public function __invoke(Request $request)
{
    Auth::logout();
    $request->session()->invalidate();

    Inertia::clearHistory(); // with 2.3.29, this also drops prefetched pages

    return redirect('/');
}
```

<Callout type="gotcha" title="A one-time refetch after you deploy">

Entries written by older versions don't have the new IV prefix. Inertia simply fetches those pages from the server again when a user goes back to them, and tabs with the old shared IV start over with a new key. Nothing breaks, but you may see a small bump in requests right after the deploy.

</Callout>

Update the adapter you use:

```bash
npm install @inertiajs/vue3@^2.3.29
```

## Laravel 12.69.3: queue timeouts and S3 credentials

Two backports from 13.x for apps still on Laravel 12.

**The worker timeout exit code is now reachable.** When a job times out, the worker kills itself with `SIGKILL`, so the exit status it meant to return never left the process. A supervisor only saw "killed by signal". This release adds `Worker::$timedOutExitCode` and a `Worker::killUsing()` hook that runs before the kill, the same as 13.x. You only need it if a process manager or platform reacts to that exit code.

**Named S3 credential providers and Cloud IAM disks.** S3 disks can use a named AWS credential provider, which is what Laravel Cloud's IAM-based disks need. If you deploy a Laravel 12 app on Cloud with S3 storage, update.

```bash
composer update laravel/framework
php artisan --version   # Laravel Framework 12.69.3
```

## Inertia Laravel 3.5.1: BigInt assertions

A follow-up to 3.5.0. With `preserveBigIntegers()` on, integers outside JavaScript's safe range are sent as `{ "$bigint": "<digits>" }` markers, so your tests had to assert against the marker. Now the testing helpers turn the markers back into integers, and you assert the value you actually passed.

<CodeCompare before="3.5.0" after="3.5.1">

```php title="tests/Feature/OrderTest.php"
$response->assertInertia(fn (AssertableInertia $page) => $page
    ->where('order.id', ['$bigint' => '900719925474099988'])
);
```

```php title="tests/Feature/OrderTest.php"
$response->assertInertia(fn (AssertableInertia $page) => $page
    ->where('order.id', 900719925474099988)
    ->hasFlash('id', 900719925474099988)
);

$this->assertSame(900719925474099988, $response->inertiaProps('order.id'));
```

</CodeCompare>

Markers are only decoded on pages that opted in with `preserveBigIntegers()`, so nothing changes if you don't use it.

## Laravel Boost 2.10.1 to 2.10.3

Three small Boost releases, mostly about better AI guidelines:

- **2.10.1** keeps syncing `CLAUDE.md` for existing Claude Code projects, uses Sail's executable in guidelines when you run Sail, and trims always-loaded guidelines that evals showed had no effect.
- **2.10.2** adds MCP support for the **Pi** agent: `boost:install` now writes `.pi/mcp.json`. It also rejects JSON5 MCP configs whose root isn't an object.
- **2.10.3** lists database tables through the schema builder for drivers Boost doesn't support directly, and fixes inaccurate guidance in four bundled skills.

<TryIt title="Update Boost and refresh its files">

```bash
composer update laravel/boost
php artisan boost:install
```

Re-running the installer refreshes your guidelines and MCP configs. Our [Boost update guide](/laravel-boost-update-vue) walks through it.

</TryIt>

These are minor releases with new features, not patches, so they get a proper write-up of their own. Short version: **1.1.0** (Oct 5) added Agent Skills support, Cohere text generation, approval for built-in tools and a `MoveFile` filesystem tool. **1.2.0** (Oct 7) added OpenAI Decisions classification and refreshed the default Anthropic models. ## Upgrade notes

- None of these releases has breaking changes. Run `composer update` or `npm update`, then your test suite.
- Inertia 2.x apps: expect pages from old history entries to be refetched once after the deploy.
- If you pin exact versions, bump them: `@inertiajs/vue3@2.3.29`, `laravel/framework:^12.69.3`, `laravel/boost:^2.10.3`.
